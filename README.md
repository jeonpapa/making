# 가족 사진관 (QR 포토월)

가족 행사용 실시간 사진 공유. 참석자가 QR로 가족 사진을 보내면 운영자가 승인하고, 대형 화면에 채팅처럼 쌓이는 피드로 보여준다. 진행자는 사진을 눌러 크게 띄우거나 고정(핀)해서 그 사진의 이야기를 나눈다.

**가을 테마:** 크림색 액자, 단풍·은행 장식, 떨어지는 낙엽, 명조체(고운바탕) 캡션. 장식은 화면에서만 입히고 **저장되는 사진 파일은 원본 그대로**라 행사 후 ZIP으로 받는 사진에는 액자가 없다. 행사 이름은 운영자 화면의 **이름 수정**으로 언제든 바꿀 수 있다 (기본값 '가족 사진관').

| 화면 | 주소 | 쓰는 사람 |
|---|---|---|
| 게스트 업로드 | `/u/[행사코드]` | 참석자 (휴대폰, 로그인 없음) |
| 운영자 승인 | `/admin` → `/admin/[행사코드]` | 승인 담당 (PIN 로그인) |
| 대형 화면 | `/wall/[행사코드]` | 진행자 노트북 (PIN 로그인 시 고정·이동 조작) |
| QR 안내판 인쇄 | `/admin/[행사코드]/qr` | 운영자 |

## 대형 화면 조작 (노트북)

| 키 / 버튼 | 동작 |
|---|---|
| **G** | 💬 모아보기 ↔ 🖼 한 장씩 크게 전환 (기본: 모아보기, 마지막 선택을 기억) |
| **Space** | 자동 스크롤 켜기/끄기 (아래로 천천히 내려가고, 맨 아래에서 5초 멈춘 뒤 처음으로) |
| 속도 버튼 | 느리게 / 보통 / 빠르게 |
| 사진 클릭 | 전체 화면 확대. **Esc** 또는 닫기로 복귀, **← →** 로 이전/다음 |
| **P** 또는 📌 버튼 | (진행자 로그인 시) 확대한 사진 고정 / 고정 해제 |
| 고정 중 **← →** | 고정을 이전/다음 사진으로 옮김 |
| **F** | 브라우저 전체 화면 |
| **Q** | 구석의 업로드 QR 보이기/숨기기 |

- **모아보기(기본):** 채팅 창처럼 모든 승인 사진이 아래로 쌓인다. 한 사람이 한 번에 보낸 사진은 한 말풍선으로 묶이고(1장 크게 / 2 / 3 / 2+2 / 3줄씩, 말풍선당 최대 9장), 보낸 사람이 바뀔 때마다 좌우가 바뀐다. 이름·아바타·캡션·시간·장수가 함께 나오고, 20분 이상 간격이 생기면 시간 구분선이 들어간다. 방금 승인된 말풍선은 8초간 은행잎 빛으로 빛나며 '🍁 방금 도착' 표시가 붙는다. 묶음 사진은 썸네일(480px)만 받아 데이터를 아낀다.
- **한 장씩 크게:** 사진 한 장씩 큰 가을 액자로 이어진다.
- 새 사진이 승인되면 자동 스크롤 중에는 그 사진으로 이동하고, 꺼져 있으면 "새 사진 N장 ↓" 버튼이 뜬다.
- 고정하면 자동 스크롤이 멈추고, 운영자 화면과 대형 화면에 같은 고정 상태가 표시된다.
- 마우스를 3초 움직이지 않으면 버튼과 커서가 사라진다.

## 사진 처리

- 휴대폰에서 고른 원본은 **최대 50MB**까지 받는다 (요즘 휴대폰 사진 5~15MB 대응).
- 브라우저에서 긴 변 1600px, JPEG 품질 0.8로 줄여서 보낸다 → 장당 보통 **150~400KB**. 썸네일(480px)도 함께 만든다.
- 아이폰 HEIC: 브라우저 기본 디코더 → `<img>` → heic2any(WASM) 순서로 시도.
- 다시 그려 저장하므로 **EXIF(GPS 위치 포함)는 지워지고 회전은 바로잡힌다.**
- 변환은 한 장씩(휴대폰 메모리 보호), 전송은 2장씩 동시에, 실패 시 1·3·9초 간격으로 재시도.

## 보안·운영 설계 (PRD 검토 반영)

- **모든 DB 접근은 서버 API(service role)로만.** RLS는 켜고 정책은 두지 않아 공개 키로는 테이블을 읽거나 쓸 수 없다. 행사 코드 목록이 새어 나가거나 게스트가 `status='approved'`로 승인을 건너뛰는 일이 생기지 않는다.
- 업로드는 서버가 발급한 **서명 업로드 URL**로 스토리지에 직접 보낸다 (Vercel 4.5MB 본문 제한 회피). 완료 시 서버가 파일 존재를 확인한 뒤에만 대기열에 넣는다.
- 업로드 제한: **기기당 분당 60장, IP당 분당 300장** (행사장 와이파이는 여러 명이 같은 IP를 쓰므로 IP 제한은 넉넉하게). 제한에 걸리면 휴대폰이 잠시 기다렸다가 자동으로 이어서 보낸다.
- 핀은 사진 상태가 아니라 `events.pinned_photo_id` 한 칸이다 (항상 0~1장). 사진을 거절·삭제하면 고정도 풀린다.
- 대형 화면은 Realtime 구독 대신 **2.5초 폴링**을 쓴다. 폴링은 행사의 `changed_at`만 비교해서 바뀐 게 없으면 55바이트만 받고, 바뀌었을 때만 사진 목록을 받는다 (300장 기준 8시간 데이터 사용량 1.75GB → 수 MB). 승인 취소된 사진이 안 사라지는 RLS+Realtime 문제와, 노트북 절전·와이파이 끊김 후 놓친 이벤트 문제를 함께 없앤다. 승인 → 화면 반영은 최대 약 3초. 연결이 끊기면 화면 구석에 "연결 끊김"이 뜨고 복구되면 자동으로 따라잡는다.
- 관리자 PIN은 서버에서 검증하고 서명된 httpOnly 쿠키(24시간)를 발급한다. 틀리면 0.8초 지연.

## 설치

### 1. Supabase

1. [supabase.com](https://supabase.com)에서 프로젝트를 만든다 (리전: Northeast Asia (Seoul)).
2. SQL Editor에서 `supabase/migrations/0001_init.sql`, `0002_changed_at.sql`을 순서대로 실행한다. 테이블, RLS, `photos` 스토리지 버킷(공개 읽기, 파일당 10MB, JPEG만)이 만들어진다.
3. Project Settings → API에서 URL, `anon` 키, `service_role` 키를 복사한다.

### 2. 환경변수

`.env.example`을 `.env.local`로 복사해 채운다. Vercel에서는 Project → Settings → Environment Variables에 같은 이름으로 넣는다.

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon 키 (서명 URL 업로드에만 쓰임) |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role 키 (**서버 전용, 절대 공개 금지**) |
| `ADMIN_PIN` | 운영자/진행자 PIN. 8자 이상 문구 권장 |
| `ADMIN_SESSION_SECRET` | `openssl rand -hex 32` 결과 |

### 3. 실행 / 배포

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 배포 전 확인
```

Vercel에 저장소를 연결하면 자동 배포된다. 배포 후 `/admin`에서 행사를 만들고, 승인 화면의 **QR 안내판 인쇄**로 안내판을 뽑는다.

> Supabase 환경변수 없이 실행하면 **메모리(테스트) 모드**로 동작한다 (PIN 기본값 `0000`, 서버 재시작 시 데이터 삭제). 화면 확인용이며 실제 행사에는 쓰지 않는다.

## 최대 몇 장까지?

| 한도 | 값 | 근거 |
|---|---|---|
| 사진 1장 원본 | **50MB** | 브라우저에서 1600px로 줄여 장당 150~400KB로 저장 |
| 한 번에 고르는 장수 | 제한 없음 | 100장 연속 테스트 68초, 실패 0 |
| 한 사람(기기) 속도 | **분당 60장** | 넘으면 자동 대기 후 이어서 전송 |
| 행사장 전체(같은 와이파이) | **분당 300장** | 같은 IP 기준 |
| 행사 전체 총량, 무료 티어 | **약 2,000~3,000장** | 저장 1GB ÷ 장당 0.35~0.45MB (본사진+썸네일 25~45KB) |
| 행사 전체 총량, Pro($25/월) | **5,000장** | 코드의 행사당 조회 한도 (저장 100GB는 여유) |

권장 운영 규모는 **1,000장 이하**다. 대형 화면 자동 스크롤은 사진 1장에 약 20초('보통' 속도)라 300장이면 한 바퀴 약 100분, 1,000장이면 5시간이 넘는다.

참석자 100명 × 평균 3장 = 300장이면 저장 약 120MB, 송신 약 200MB로 무료 한도(1GB / 5GB) 안에 넉넉히 들어간다. Supabase 무료 프로젝트는 1주 무활동 시 일시정지되므로 **행사 전날 `/admin`에 한 번 접속**해 깨워 둔다.

## 행사 당일 체크

- 노트북: 유선 LAN, 절전·화면보호기·알림 끄기, `/wall/[코드]` 열고 진행자 로그인 → **F**로 전체 화면
- 승인 담당: 별도 기기에서 `/admin/[코드]`
- 30분 전 실제 휴대폰(아이폰 HEIC + 안드로이드)으로 업로드 → 승인 → 화면 표시 확인
- 행사 후: 승인 화면에서 **승인 사진 ZIP** 다운로드 (사진 + `captions.tsv`) → 보관 기간 후 삭제

## 검증 결과 (메모리 모드, Chromium E2E)

33개 항목 통과: 잘못된 PIN·코드 거부, 기본 행사 이름·이름 수정, 변경 없을 때 폴링 55바이트, 비로그인 API 차단, **15.6MB·24MP JPEG / HEIC / EXIF 회전 / PNG** 업로드(4장 4.9초, 모두 1600px·300KB 이하로 변환, 회전 정상), 승인 → 화면 반영 2.2초, 승인 취소 → 0.8초 내 사라짐, 확대·Esc, 고정·고정 중 다음 이동·운영자 화면 동기화·해제, 자동 스크롤 동작·Space 끄기, 업로드 off 시 화면 안내와 API 차단, **100장 연속 업로드 68초·실패 0건**.

실기기(아이폰 Safari, 안드로이드 Chrome)와 실제 Supabase 연결 테스트는 아직 하지 않았다. 배포 후 위 당일 체크로 확인할 것.
